# The Family Auto

Современный React/Vite-сайт автосалона: 20 моделей Toyota, Mercedes-Benz, Honda и Lamborghini; кыргызский, русский и английский языки; адаптивная вёрстка.

## Запуск

```powershell
npm install
npm run dev
```

Откройте адрес Vite из терминала (обычно `http://localhost:5173`). REST API и Socket.io запускаются плагином Vite. При первом запросе каталога создаётся `data/store.json`.

Администратор для локальной демонстрации: зарегистрируйте `admin@example.com`. Для другого email задайте `ADMIN_EMAIL` в `.env`. JWT подписывает backend; пароль сохраняется как scrypt hash. API для управления каталогом и статистики проверяет роль администратора.

## Публикация на Vercel через GitHub

1. Убедитесь, что в GitHub загружены папки `api/`, `src/` и файл `vercel.json`.
2. В Vercel задайте Root Directory как папку проекта с `package.json`, `api/` и `vercel.json`, Build command — `npm run build`, Output directory — `dist`, затем нажмите **Redeploy** (или отправьте новый commit в подключённую ветку). Node.js 24.x закреплён в `package.json`.
3. В Vercel → **Settings → Environment Variables** добавьте `JWT_SECRET` со случайным длинным значением и `ADMIN_EMAIL` с адресом администратора. Если нужны постоянные заказы, аккаунты, отзывы и изменения каталога, подключите Upstash Redis и добавьте `TFA_STORE_URL` и `TFA_STORE_TOKEN` из его REST API credentials.
4. После успешного deployment откройте `https://ваш-домен.vercel.app/api/cars`. Ответ должен быть JSON-массивом автомобилей. Затем обновите сайт на телефоне.

Vercel запускает API из папки `api/` как serverless functions; Socket.IO на продакшене выключен, а статус заказа обновляется периодическим запросом. Без `TFA_STORE_URL` и `TFA_STORE_TOKEN` сервер использует временное хранилище в памяти, поэтому заказы и прочие изменения могут сбрасываться при перезапуске функции. Демо OAuth и демо-оплата не требуют дополнительных ключей.

### Уведомления о заказах в Telegram

API отправляет владельцу сообщение при новой покупке, бронировании и заявке из формы контактов. Для включения уведомлений:

1. Создайте бота через `@BotFather` командой `/newbot` и скопируйте токен. Не публикуйте токен в GitHub и не вставляйте его в React-код.
2. Откройте своего нового бота в Telegram и нажмите **Start**. Узнайте свой Telegram chat ID через бота `@userinfobot`.
3. В Vercel откройте **Settings → Environment Variables** и добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Сохраните секреты и выполните новый Deploy.
4. Проверьте отправку тестовой заявкой с сайта. Если настройки добавлены только для локального запуска, поместите их в свой `.env` и перезапустите `npm run dev`.

Заказы требуют, чтобы приложение было развёрнуто с API из `api/`. Без этих двух переменных заявки остаются доступны в админ-панели, но бот не получит уведомления.

## Функции

- Корзина, избранное, заказ, бронь, регистрация и вход с JWT.
- Отдельные страницы регистрации и входа (`/register`, `/login`); бургер-меню доступно на больших и маленьких экранах.
- Бронирование сохраняется в API и открывает готовую заявку в WhatsApp на номер `+996 999 42 5453`.
- Отдельная страница `/booking` с именем, телефоном, автомобилем, личной встречей, тест-драйвом или онлайн-консультацией и комментарием; выбранная модель подставляется автоматически.
- Кнопка «Купить сейчас» открывает оформление выбранного автомобиля; оставить отзыв можно в разделе отзывов.
- Оформление заказа вынесено на отдельную страницу `/order`; после подтверждения открывается личное отслеживание `/tracking?reference=...`.
- Страница отслеживания показывает этап доставки и схематичный маршрут по Бишкеку. Процент пути и положение автомобиля автоматически меняются каждые 2 секунды в демо-режиме; менеджер также может менять этапы в админ-панели. Это не GPS-трекинг: для реального местоположения понадобится отдельный сервис геолокации/карт.
- Чтобы посмотреть ранее созданный заказ, откройте «Отследить заказ» в меню и введите номер заказа. Нужен тот же аккаунт, которым оформлялась покупка.
- Каталог с поиском, фильтрами и пагинацией.
- Админ CRUD: добавить, изменить и удалить машину; статистика графиком.
- Skeleton загрузки, React Error Boundary и demo chatbot.
- Socket.io отправляет обновления каталога и отзывов в реальном времени.
- Telegram и SMTP email уведомления при наличии данных в `.env`.
- Cloudinary загрузка при настройке unsigned upload preset.
- Google/GitHub OAuth endpoints с настоящим OAuth при настройке client credentials; кнопки работают в demo-режиме без ключей.
- Stripe/Post.kg выбор оплаты в интерфейсе и demo endpoint. Реальные платежи не списываются.

## Подключение внешних сервисов

Скопируйте `.env.example` в `.env`, заполните параметры сервиса и перезапустите Vite. Никогда не публикуйте `.env` и не добавляйте секретные ключи с префиксом `VITE_`: переменные `VITE_*` доступны браузеру. Только Cloudinary cloud name и unsigned preset являются публичными значениями.

Для OAuth задайте client ID/secret, добавьте callback адреса из `.env.example` в настройках Google/GitHub и включите `VITE_GOOGLE_OAUTH_ENABLED`/`VITE_GITHUB_OAUTH_ENABLED`. Для Telegram и email укажите bot/chat или SMTP-реквизиты. Для Cloudinary укажите cloud name и unsigned preset.

Stripe и Post.kg здесь подключены только как демонстрационные способы оплаты. Для реального приёма денег нужно создать checkout на защищённом backend, настроить merchant аккаунт и подтверждение платежа/webhook; не храните платёжные секреты в React.

## API

- `GET /api/cars`; `POST/PUT/DELETE /api/cars` — CRUD, администратор.
- `GET/POST /api/reviews` — отзывы.
- `POST /api/auth`, `GET /api/me`, `GET /api/oauth/{google|github}` — auth и OAuth.
- `GET /api/admin/stats` — статистика, администратор.
- `POST /api/orders`, `POST /api/payments`, `POST /api/bookings` — заказ, демо-оплата и бронь.
- `GET /api/orders/:reference` — статус своего заказа; `GET /api/admin/orders` и `PATCH /api/admin/orders/:reference` — управление этапом доставки администратором.
